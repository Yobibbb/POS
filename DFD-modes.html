Figure 1
Firebase Mode — Cloud Operation

Firebase Mode Data Flow Diagram

In Firebase Mode, the Mobile Application communicates directly with Firebase cloud services. Product catalog and basket data are fetched from D1 – Firestore by process 1.0 Fetch Product and Basket Data. The ESP32 Smart Basket pushes barcode scan events directly to D2 – Firebase RTDB; process 2.0 Process Scan Events listens to RTDB in real time and forwards updated basket items to the Mobile App. When a session ends, process 3.0 Record Session and Transaction writes the completed session and transaction history back to Firestore. Any writes that occur during a brief connectivity interruption are buffered in D3 – Offline Write Queue by Firebase's built-in offline persistence; process 4.0 Sync Offline Writes flushes this queue to Firestore once the connection is restored.

Figure 2
Local Server Mode — On-Premise Operation

Local Server Mode Data Flow Diagram

In Local Server Mode, all communication is routed through the Node.js local server over a dedicated Wi-Fi hotspot. The Mobile Application sends an HTTP GET request to process 1.0 Serve Product Data, which reads records from D1 – products.json stored on disk and returns the product list. The ESP32 Smart Basket polls the local server for session assignments and posts barcode scans to process 2.0 Handle Basket Scan Events, which persists state in D2 – In-Memory Session Store and writes scan events to D3 – Socket.IO Event Bus. Process 3.0 Manage Checkout and Transactions handles checkout requests from the Mobile App and payment confirmations from the POS Frontend, recording the completed transaction in D2 and writing the closing event to D3. Process 4.0 Dispatch Real-time Notifications reads events from D3 and pushes them to all connected clients via Socket.IO — delivering item_added and item_removed to the Mobile App, checkout_requested to the POS Frontend, and checkout_complete back to the Mobile App.
